# Kanji 5 v1.7 roadmap

## Goal
Make recall adaptive at the level of the individual learning attribute, not only at the card/session level.

## P0 — Adaptive multi-attribute recall
- Model knowledge independently for meaning, reading, production, vocabulary, and context.
- Rank attributes by weakness and uncertainty.
- Generate a recall plan containing one primary and optionally one secondary attribute.
- Keep FSRS scheduling card-level; adaptive recall decides which knowledge attribute to probe next.
- Persist enough session state to resume the same adaptive plan without losing intent.
- Add E2E coverage for switching attributes after weak answers and for unseen attributes.

## P1 — Learning UX
- Show the learner which attribute is being trained and why.
- Keep the primary review flow learning-first; dashboard remains secondary.
- Surface less-common readings only when evidence says the learner needs them.

## P2 — Evaluation and tuning
- Measure per-attribute accuracy, uncertainty, and recovery after errors.
- Tune attribute selection against user outcomes rather than UI events alone.
- Preserve backward compatibility with v1.6 knowledge/session data.

## Non-goals
- Do not replace FSRS with a second scheduling system.
- Do not add dashboard complexity before the adaptive recall loop proves useful.
- Do not make every session multi-attribute by default; adapt only when evidence supports it.
