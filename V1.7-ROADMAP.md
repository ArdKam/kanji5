# Kanji 5 v1.7 roadmap

## Product goal
Make recall adaptive at the level of the individual learning attribute, not only at the card/session level, while preserving the v1.6 learning-first flow and FSRS scheduling.

## Priority order

### P0-A — Adaptive decision core ✅
- Model knowledge independently for meaning, reading, production, vocabulary, and context.
- Rank attributes by weakness and uncertainty.
- Generate a recall plan containing one primary and optionally one secondary attribute.
- Keep FSRS scheduling card-level; adaptive recall decides which knowledge attribute to probe next.

### P0-B — Adaptive recall integration ✅
- Feed the existing Active Recall entry point from the adaptive selector.
- Keep the current meaning/reading input contract backward-compatible.
- Persist the selected attribute through the existing per-attribute knowledge record.
- Add E2E coverage proving weak-attribute selection changes the next recall prompt.
- Extend the runtime prompt surface to production/vocabulary/context only after those modes have a valid learner-facing response and grader.

### P0-C — Session continuity ✅
- Persist enough adaptive-plan state to resume the same intent after reload.
- Ensure session-finished remains the single lifecycle event; adaptive consumers must not own session lifecycle.
- Verify active recall, session history, analytics, and skill-profile data survive refresh/finish flows.

### P1 — Learning UX
- Show the learner which attribute is being trained and a concise reason when useful.
- Keep the primary review flow learning-first; dashboard remains secondary.
- Surface less-common readings only when evidence says the learner needs them.
- Avoid adding new dashboard surfaces until adaptive recall improves the actual review loop.

### P2 — Evaluation and tuning
- Measure per-attribute accuracy, uncertainty, and recovery after errors.
- Compare adaptive selection against a stable baseline using persisted learner outcomes, not UI events alone.
- Tune thresholds, recency weighting, and secondary-attribute selection.
- Preserve backward compatibility with v1.6 knowledge/session data.

## Current implementation status
- Adaptive multi-attribute scoring core: complete and covered by automated tests.
- Active Recall prompt selection: integrated for the currently supported meaning/reading prompts; production/vocabulary/context remain gated until a real prompt + grader exists.
- v1.7 CI: active and test-backed.

## Non-goals
- Do not replace FSRS with a second scheduling system.
- Do not add dashboard complexity before the adaptive recall loop proves useful.
- Do not make every session multi-attribute by default; adapt only when evidence supports it.
- Do not expose a fake production/vocabulary/context recall mode without a real learner-facing exercise and grader.
