# Kanji 5 v1.8 roadmap

## Product goal
Turn the v1.7 adaptive-recall infrastructure into richer learner-facing exercises while preserving FSRS as the card-level scheduler and keeping the review flow learning-first.

## Priority order

### P0-A — Production Recall 🔄
- Use a real learner input rather than only multiple-choice selection.
- Prompt from canonical English meaning and require production of the target Kanji.
- Grade production with a dedicated deterministic grader.
- Record production outcomes through the existing education state/session boundary.
- Add unit and browser coverage for correct, wrong, empty, and persistence paths.
- Keep the exercise usable offline; the production grader must not depend on a remote API.

### P0-B — Vocabulary Recall
- Introduce a learner-facing vocabulary exercise with a real grader.
- Persist vocabulary outcomes separately from meaning/reading/production.
- Use external vocabulary data only as content support, not as the grading authority.

### P0-C — Context Recall
- Introduce a learner-facing context exercise with a real grader.
- Persist context outcomes separately from other attributes.
- Preserve safe API caching and offline fallback behavior.

### P1 — Adaptive Recall 2.0
- Rebalance multi-attribute planning using real supported modes.
- Use recent errors and recovery evidence to influence sequencing.
- Keep FSRS card scheduling unchanged.

### P2 — Evaluation 2.0
- Track longitudinal learner outcomes by attribute.
- Compare adaptive and stable-baseline cohorts only when evidence is sufficient.
- Keep evaluation independent from the grading implementation.

### P3 — Learner Model
- Improve attribute-level mastery and trend estimates.
- Surface Kanji-specific weaknesses to the planner.

### P4 — Learning UX
- Add minimal progress feedback.
- Explain adaptive exercise choices when useful.
- Improve retry/hint flow without adding dashboard complexity.

### P5 — Data and runtime quality
- Version richer learner outcomes and grader contracts.
- Preserve offline-first behavior and deterministic migrations.

### P6 — Engineering
- Unit, integration, browser E2E, service-worker, and release-contract coverage for each new mode.
- Keep `npm test` as the local aggregate contract entry point.

## Definition of done
- Production, Vocabulary, and Context each have real learner-facing exercises and deterministic graders before the corresponding adaptive modes are fully enabled.
- Adaptive selection consumes only supported, test-backed modes.
- Learner outcomes are durable and distinguishable by attribute.
- CI, browser E2E, runtime wiring, and release contracts are green.
